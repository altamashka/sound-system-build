# Sound system build

Read `context/workshop.md`, `README.md` and `SKRAM + JMOD Build Plan.md` for scope and open decisions. Use `Wood sourcing review.md` for dated procurement evidence, `Build Guide.md` for fabrication and `Sound Setup Guide.md` for operation. Do not silently merge these into another duplicate handbook.

The local designer packages are excluded from the initial remote repo; inspect actual files before claiming CAD/CAM validation. Do not fabricate machine simulations, tool compatibility, acoustic tests or a safe limiter setting from an unsupported assumption. Keep source attribution and distinguish designer data, calculations, owner reports, live observations and unresolved checks.

Preserve the current project decisions and cabinet geometry. JMOD/SKRAM work calls for its own birch stock, CAM/thickness and acoustic/wiring specifications; the kitchen project's oak choice does not apply. Changes affecting driver/cabinet compatibility, output/limiting, electrical operation, expenditure or collective preferences need the user's decision and appropriate verification.

Use plain English and beginner-friendly steps. Alt Makers is a shared workshop/material-ordering route, not an assumed commissioning/design service. No supplier messages, purchases, bookings, deployments or powered-system tests without explicit instruction. Do not commit designer originals through ordinary Git, credentials, device state or backups. Shared `context/workshop.md` is generated by workshop-reference/tools/sync_workshop_context.py.

Keep this checkout self-contained for phone/cloud use. If an original file is absent, say so rather than relying on a parent folder or old conversation. No software installation is needed just to read or edit the Markdown guides.

## Git workflow (Claude and Codex)

`main` holds the reviewed documents. Make each change on its own branch and open a pull request into `main`; do not push straight to `main`. Claude and Codex should not work on the same branch at the same time. The guides are long single files, so pull the latest `main` before editing, keep each PR to one topic or section, and rebase rather than hand-merge if two PRs touch the same guide.

This repo is the current copy of the guides. Other copies (for example an uploaded project folder) may be older snapshots: check the date line at the top of a guide before trusting it, and do not copy an older version over a newer one. Never edit `context/workshop.md` by hand. `Notes/` holds dated working notes; newer guide text wins where they disagree.
